# 현장 설비 데이터 수집 시스템 — 개요 보고서

> 대상: 기획·운영·영업 등 비개발 담당자 포함 전원
> 범위: `collector-plc`(PLC 수집기) + `Embedded_ingest`(현장 데이터 서버)
> 기준일: 2026-09-29

---

## 1. 한눈에 보기

- 공장 설비(PLC)와 센서의 데이터를 **현장에 설치한 소형 PC(엣지 장비)** 가 자동으로 읽어서 저장하고, **하루 한 번 본사 서버로 올리는** 시스템입니다.
- 프로그램은 두 개로 나뉩니다.
  - **수집기(`collector-plc`)**: 설비 PLC에 접속해 정해진 주기(기본 1초)로 값을 읽습니다.
  - **데이터 서버(`Embedded_ingest`)**: 무엇을 읽을지 지시하고, 받은 값을 저장하고, 본사로 전송합니다.
- **어떤 설비의 어떤 값을 읽을지는 엑셀 파일로 관리**합니다. 코드를 고치지 않아도 엑셀만 바꾸면 수집 항목을 늘리거나 줄일 수 있습니다.
- 통신이 끊겨도 프로그램이 멈추지 않고 **자동으로 다시 연결**하며, 일부 항목만 오류가 나도 **나머지 항목은 계속 수집**합니다.

---

## 2. 시스템 구성도

```text
 [공장 설비]                     [현장 엣지 PC]                               [본사]

  PLC (LS / 미쓰비시 등) ──┐
  PLC ─────────────────────┤──▶  ① 수집기 ──(내부 통신)──▶ ② 데이터 서버 ──(하루 1회)──▶ 본사 서버
  PLC ─────────────────────┘      collector-plc      ◀──(명령)──  Embedded_ingest     (일별 로그 업로드)
                                                                   │   ▲
  센서 보드 (시리얼 케이블) ─────────────────────────────────────────┘   │
  이물 검출 카메라 (이미지) ─────────────────────────────────────────────┘
                                                                   │
                                                              엑셀 설정 파일
                                                         (장치 목록 · 수집 항목표)
```

- ①과 ②는 **같은 현장 PC 안에서** 동작하며, 서로 내부 메시지로 대화합니다.
- 본사와는 인터넷(HTTP)으로 통신합니다.

---

## 3. 구성 요소별 역할

### ① 수집기 — `collector-plc`

| 항목 | 내용 |
|------|------|
| 하는 일 | PLC에 접속해 지정된 메모리 주소의 값을 주기적으로 읽고, 결과를 데이터 서버로 넘깁니다 |
| 동시 처리 | 한 현장의 PLC 여러 대를 **한 프로그램이 동시에** 담당합니다 (장비마다 별도 작업 흐름) |
| 읽는 값의 종류 | 숫자(워드), ON/OFF 신호(비트), 큰 숫자(2워드 이상), 문자열(모델명 등) |
| 보고하는 내용 | ▸ 수집 데이터 ▸ 장비 연결 상태(정상/끊김) ▸ 명령 처리 결과(성공/실패) |
| 설정 변경 | 데이터 서버의 지시를 받아 **수집 항목·주기 변경**, **접속 정보 변경**을 재시작 없이 반영하고 파일에도 저장합니다 |

### ② 데이터 서버 — `Embedded_ingest`

| 항목 | 내용 |
|------|------|
| 설정 배포 | 엑셀의 `PLC 장치 셋팅`(어느 PLC에 어떻게 접속할지)과 `PLC 메모리 맵`(무엇을 읽을지)을 읽어 수집기에 전달합니다. 기동할 때 자동으로 1회 수행합니다 |
| 데이터 저장 | 수집기가 보낸 값에 엑셀의 **항목 이름**(예: "브로칭 생산수량")을 붙여 현장 PC의 데이터베이스(SQLite)에 저장합니다 |
| 로그 파일 | 회사·장비별로 **하루 단위 로그 파일**을 만듭니다 |
| 본사 전송 | 매일 새벽 1시에 **전날 로그 파일**을 본사 서버로 업로드합니다. 실패하면 다음 회차에 자동 재시도(최대 5회) |
| 센서 수집 | 시리얼 케이블로 연결된 센서 보드(온도·습도·기압·풍속 등)의 값을 받아 저장하고 본사로 전달합니다 |
| 이물 검출 | 카메라 검출 결과(이미지 + 검출 여부)를 받아 본사로 보내고, 시리얼로 현장 장비에 결과를 알려줍니다 |
| 관리 화면 | 웹 API로 상태 조회·수동 실행이 가능합니다 (예: 수집 현황, 업로드 상태, 최근 데이터 조회) |

## 4. 데이터가 흐르는 순서

1. **설정 준비** — 담당자가 엑셀에 장비 접속 정보와 수집 항목을 작성합니다.
2. **설정 배포** — 데이터 서버가 켜지면 엑셀 내용을 수집기에 전달합니다. 수집기는 "적용 완료"를 회신합니다.
3. **주기 수집** — 수집기가 장비마다 정해진 주기(기본 1초, 장비별 조정 가능)로 PLC 값을 읽습니다.
4. **전달·저장** — 읽은 값이 데이터 서버로 전달되고, 항목 이름이 붙어 DB와 일별 로그 파일에 기록됩니다.
5. **본사 업로드** — 다음 날 새벽 1시, 전날 로그 파일이 회사·장비 단위로 본사에 업로드됩니다.

> 수집 항목이나 주기를 바꾸고 싶을 때는 엑셀을 수정한 뒤 데이터 서버에서 "적용"만 다시 실행하면 됩니다. PLC 연결을 끊지 않고 반영됩니다.

## 5. 지원하는 설비·통신 방식

| 통신 방식 | 대표 제조사 / 용도 | 연결 방법 |
|-----------|--------------------|-----------|
| XGT 전용 프로토콜 | LS산전 XGT PLC | 이더넷 (보통 2004 포트) |
| MC 프로토콜 | 미쓰비시 PLC | 이더넷 |
| Modbus TCP | 범용 (LS XG 등) | 이더넷 |
| Modbus RTU | 범용 | 시리얼(RS-485/232) |

**현재 문서화된 현장 사례 — 대승정밀 (LS XGT)**
주조 후공정 라인의 PLC에서 `D490000~D490135` 구간(136개 값)을 읽습니다. 포함 항목은 다음과 같습니다.

- 공정별 상태: 적재파렛트, 레이저마킹, 브로칭, 다축드릴, 자동시험기, 리벳압입, ABB 디버링 로봇, 현대 로봇, AMR(무인운반차), 파렛 보관소
- 생산 정보: 사이클 타임, 생산수량·총생산수량, 목표수량, 모델명
- 경보: 비상정지, 모터 트립, 서보 에러, 통신 에러, 사이클 타임 초과, 공구 사용수량 초과 등

본사 업로드 대상 회사 코드는 현재 `DONGHAE`, `DAESEUNG`(대승정밀), `DH_AUTOLEAD`(DH오토리드) 세 곳이 설정되어 있습니다.

## 6. 안정성 — 문제가 생기면 어떻게 되나

| 상황 | 시스템 동작 |
|------|-------------|
| PLC 전원 꺼짐·케이블 빠짐 | 해당 장비만 "연결 끊김"으로 보고하고 **5초마다 자동 재접속**. 다른 장비는 영향 없음 |
| 특정 주소만 읽기 실패 (예: 없는 번지) | 그 항목만 값 없음 + 오류 코드로 기록. **나머지 항목은 정상 수집** |
| 잘못된 설정이 전달됨 | 적용을 거부하고 사유를 회신. **기존 설정으로 계속 동작** |
| 현장 PC 재부팅 | 두 프로그램 모두 **자동 시작**. 데이터 서버는 수집기가 먼저 켜질 때까지 최대 2분 대기 |
| 프로그램 비정상 종료 | 5초 후 자동 재시작 |
| 본사 업로드 실패 | 다음 회차에 자동 재시도 (최대 5회), 성공·실패 이력을 DB에 기록 |

### 오류 코드 읽는 법

로그나 데이터에 `E-` 로 시작하는 코드가 보이면 **첫 숫자**로 원인 분류를 알 수 있습니다.

| 코드 | 의미 | 담당자가 확인할 것 |
|------|------|--------------------|
| `S-0000` | 정상 | — |
| `E-1xxx` | 장비 연결 문제 | PLC 전원, 네트워크 케이블, IP 주소 |
| `E-2xxx` | 값 읽기/쓰기 실패 | `E-2203`은 "PLC에 그 주소가 없음" → 수집 항목표의 주소 확인 |
| `E-3xxx` | 장비 응답 이상 | PLC 설정, 통신 방식 선택이 맞는지 |
| `E-4xxx` | 설정·요청 오류 | 엑셀의 주소 표기(오타), 장비 이름 일치 여부 |
| `E-9xxx` | 기타 내부 오류 | 개발 담당자에게 전달 |

## 7. 데이터 보관 정책 (현장 PC 기준)

| 대상 | 보관 기간 | 비고 |
|------|-----------|------|
| 운영 로그 파일 | 7일 | 기간이 지나면 자동 정리 (본사 업로드는 매일 새벽에 먼저 수행) |
| 이물 검출 이미지 | 60일 | 자동 정리 |
| 수집 데이터(DB) | 별도 삭제 정책 없음 | 장기 운영 시 디스크 용량 점검 필요 |

## 8. 현재 한계 및 확인이 필요한 사항

아래 항목은 운영 전에 담당자 확인 또는 개발 일정 반영이 필요합니다.

| 구분 | 내용 | 영향 | 권장 조치 |
|------|------|------|-----------|
| 기능 미구현 | **PLC에 값을 쓰는(제어) 명령**은 수집기가 받기만 하고 실행하지 않습니다. "1회 읽기", "수집 중지" 명령도 미지원 | 현재는 **읽기 전용 시스템** | 제어 기능이 필요하면 개발 일정 편성 |
| 설정 주의 | 두 프로그램의 **예시 설정 파일 기본 통신 포트가 서로 엇갈려** 있습니다 (둘 다 같은 포트를 열려고 함) | 예시 그대로 설치하면 두 프로그램이 서로 통신하지 못함 | 설치 시 수집기 쪽 포트를 서로 맞게 바꿔 설정 (설치 가이드에 명시) |
| 현장 데이터 | 대승정밀 데이터맵에서 `D490011` 한 주소에 두 항목(직교 Z축 위치 / 완성파렛 수량)이 겹쳐 있고, 자동시험기 `D490066.5` 표기가 불규칙합니다 | 해당 항목 값이 잘못 해석될 수 있음 | PLC 담당자와 확정 |
| 현장 데이터 | PLC와 PC 사이에 비트 순서가 뒤집혀 보일 가능성이 문서에 언급되어 있습니다 | ON/OFF 신호가 다른 항목으로 보일 수 있음 | 현장에서 신호 1개로 실제 값 대조 |
| 보안 | 데이터 서버가 기동 시 설정 전체(본사 업로드용 API 키 포함)를 화면·시스템 로그에 출력합니다 | 로그 열람 권한자에게 키 노출 가능 | 출력 제거 또는 키 가림 처리 |
| 기능 상태 | 이물 검출 결과의 **현장 DB 저장이 꺼져 있습니다** (본사 전송·시리얼 알림은 동작) | 현장 PC에 검출 이력이 남지 않음 | 의도된 설정인지 확인 |
| 용량 | 수집 데이터 DB는 자동 삭제되지 않습니다 | 1초 주기 × 다수 항목이면 장기적으로 용량 증가 | 보관 기간 정책 결정 |

## 9. 용어 설명

| 용어 | 쉬운 설명 |
|------|-----------|
| PLC | 공장 설비를 제어하는 산업용 컴퓨터. 설비 상태·수량 등이 내부 메모리에 저장되어 있음 |
| 메모리 주소 (예: `D490000`) | PLC 안에서 값이 저장된 위치의 번호. "몇 번 칸에 무엇이 있다"는 약속 |
| 비트 (예: `D490000.0`) | 한 칸 안의 ON/OFF 신호 하나 (운전 중, 알람 발생 등) |
| 워드 | 숫자 하나를 담는 칸 (-32768 ~ 32767 범위) |
| 엣지 장비 | 공장 현장에 두는 소형 PC. 설비 가까이서 데이터를 먼저 모으는 역할 |
| 수집 주기 | 값을 몇 초마다 읽을지 (기본 1초) |
| `device_key` | 시스템 안에서 PLC 한 대를 부르는 고유 이름 (예: `plc-ls-xgt-1`). 엑셀과 수집기 설정에서 같아야 함 |
| ACK | "명령 잘 받았고 처리했다"는 회신 |

## 부록 — 운영 담당자 자주 쓰는 확인 방법

| 확인하고 싶은 것 | 방법 (데이터 서버 웹 API, 기본 포트 8000) |
|------------------|--------------------------------------------|
| 서버가 살아 있는지 | `GET /api/health` |
| PLC 데이터가 들어오고 있는지 | `GET /api/plc/data/worker/status` (마지막 수신 시각, 성공·실패 건수) |
| 최근 수집 값 | `GET /api/plc/samples?device_key=장비이름` |
| 엑셀 설정 다시 적용 | `POST /api/plc/devices/apply` |
| 본사 업로드 상태 | `GET /api/logs/upload/status` |
| 본사 업로드 수동 실행 | `POST /api/logs/upload` |

웹 브라우저에서 `http://현장PC주소:8000/docs` 로 접속하면 위 기능을 화면에서 바로 실행해 볼 수 있습니다.
