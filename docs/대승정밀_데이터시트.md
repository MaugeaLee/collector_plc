# 대승정밀 — XGT E_NET 데이터시트

캠텍 PC가 LS XGT PLC(E_NET 서버)에서 읽어가는 **메모리맵**과 **전용(Dedicated) 프로토콜 예시 프레임** 정리.  
원본: `데이터맵.xlsx` (시트: `통신데이터`, `PLC통신설정` / EFMTB 통신매뉴얼 7장 서버서비스).

---

## 1. 통신 개요

| 항목 | 내용 |
|------|------|
| 방향 | PC(클라이언트) → PLC(XGT 서버) 읽기 |
| 프로토콜 | LS **XGT Dedicated** (Company Header `LSIS-XGT`) |
| 전송 | TCP 소켓 (E_NET 전용 포트, 보통 **2004** — PLC 설정 확인) |
| 캠텍 읽기 대역 | **`D490000` ~ `D490135`** (워드 136개 = 바이트 272) |
| 연속읽기 시작주소 | `%DB980000` (`D490000` × 2) |
| PLC 원본 | M / P / D / C 등 → PLC 측에서 캠텍 대역으로 모은 값 |
| CPU (문서 예시) | XGK (`CPU Info = 0xA0`), 예: XGK-CPUHN |

- E_NET 포트는 **외부망과 분리** 권장.
- **PLC bit0 ↔ PC bit15**로 비트 순서가 뒤집혀 보일 수 있음 → 현장 값으로 검증.

### 주소 표기

| 표기 | 의미 |
|------|------|
| `D490000` | D 워드 490000 |
| `D490000.0` ~ `.9` / `.A` ~ `.F` | 워드 내 비트 0~9 / 10~15 |
| `%DW490000` | 개별 WORD 읽기용 직접변수 |
| `%DB980000` | 연속 BYTE 읽기용 직접변수 (워드×2) |

collector-plc scan 예: `D490000`, `D490000.0`, `D490130.A`.

## 3. 프로토콜 & 예시 프레임

멀티바이트 = **Little Endian**.  
프레임 = **Company Header(20)** + **Application**.

### 3.1 Company Header

| Offset | Size | 필드 | 요청 | 응답 |
|--------|------|------|------|------|
| 0 | 10 | Company ID | `LSIS-XGT` + `00 00` | 동일 |
| 10 | 2 | PLC Info | `00 00` | CPU/상태 채워짐 |
| 12 | 1 | CPU Info | `A0` 또는 `00` | `A0` 등 |
| 13 | 1 | Source | `33` Client→PLC | `11` PLC→Client |
| 14 | 2 | Invoke ID | 임의 | 요청 echo |
| 16 | 2 | Length | App 바이트 수 | App 바이트 수 |
| 18 | 1 | Position | `00` | 슬롯 등 |
| 19 | 1 | BCC/Reserved | `00` | 값 |

Company ID HEX: `4C 53 49 53 2D 58 47 54 00 00`

### 3.2 Command / Data Type

| 구분 | Command (와이어) | Data Type |
|------|------------------|-----------|
| 읽기 요청 | `54 00` | 개별 WORD=`02 00` / 연속 BYTE=`14 00` |
| 읽기 응답 | `55 00` | 요청과 동일 |
| 쓰기 요청/응답 | `58 00` / `59 00` | (본 시트는 읽기 중심) |

| Data Type | 모드 |
|-----------|------|
| `00 00` BIT / `01 00` BYTE / `02 00` WORD / `03 00` DWORD / `04 00` LWORD | 개별 |
| `14 00` BYTE | **연속만** (Block Count 항상 1) |

### 3.3 예시 A — 연속 읽기 (권장: 전체 맵 272B)

**목적:** `D490000`~`D490135` = 136워드 = 272바이트  
**주소:** `%DB980000`  
**Invoke ID:** `0x0001`

#### 요청 (Client → PLC) — 총 42바이트

| Offset | Size | 필드 | HEX | 설명 |
|--------|------|------|-----|------|
| 0 | 10 | Company ID | `4C 53 49 53 2D 58 47 54 00 00` | LSIS-XGT |
| 10 | 2 | PLC Info | `00 00` | Don't care |
| 12 | 1 | CPU Info | `A0` | XGK |
| 13 | 1 | Source | `33` | Client→Server |
| 14 | 2 | Invoke ID | `01 00` | 1 |
| 16 | 2 | Length | `16 00` | App=22 |
| 18 | 1 | Position | `00` | |
| 19 | 1 | BCC | `00` | |
| 20 | 2 | Command | `54 00` | Read |
| 22 | 2 | Data Type | `14 00` | Continuous Byte |
| 24 | 2 | Reserved | `00 00` | |
| 26 | 2 | Block Count | `01 00` | 1 |
| 28 | 2 | Var Length | `0A 00` | 10 |
| 30 | 10 | Var Name | `25 44 42 39 38 30 30 30 30` | `%DB980000` |
| 40 | 2 | Data Count | `10 01` | 272 (`0x0110`) |

원본 HEX (한 줄):

```text
4C 53 49 53 2D 58 47 54 00 00 00 00 A0 33 01 00 16 00 00 00
54 00 14 00 00 00 01 00 0A 00 25 44 42 39 38 30 30 30 30 10 01
```

#### 응답 (PLC → Client) — Header 20 + App (정상 시 Data 272B)

| Offset | Size | 필드 | 예시 HEX | 설명 |
|--------|------|------|----------|------|
| 0 | 10 | Company ID | `4C 53 49 53 2D 58 47 54 00 00` | |
| 10 | 2 | PLC Info | `xx xx` | CPU/상태 |
| 12 | 1 | CPU Info | `A0` | |
| 13 | 1 | Source | `11` | Server→Client |
| 14 | 2 | Invoke ID | `01 00` | echo |
| 16 | 2 | Length | `1C 01` | App=284 (`8+2+2+272`) ※모듈별 확인 |
| 18 | 1 | Position | `xx` | |
| 19 | 1 | BCC | `xx` | |
| 20 | 2 | Command | `55 00` | Read ACK |
| 22 | 2 | Data Type | `14 00` | Continuous |
| 24 | 2 | Reserved | `00 00` | |
| 26 | 2 | Error Status | `00 00` | 0=정상 |
| 28 | 2 | Block/Var count | `01 00` | |
| 30 | 2 | Data Count | `10 01` | 272 |
| 32 | 272 | Data | `…` | 바이트 스트림 |

응답 원본 HEX 골격:

```text
4C 53 49 53 2D 58 47 54 00 00 .. .. A0 11 01 00 .. .. .. ..
55 00 14 00 00 00 00 00 01 00 10 01
[Data 272 bytes: D490000 low, D490000 high, D490001 low, ...]
```

**Data 해석 예** (앞 4바이트가 `01 00 00 00`이면):

```text
Data[0]=0x01, Data[1]=0x00  →  D490000 = 0x0001  →  bit0(자동운전 선택)=ON
Data[2]=0x00, Data[3]=0x00  →  D490001 = 0x0000
```

### 3.4 예시 B — 연속 읽기 (작은 블록: 상태 워드만 2바이트)

**목적:** `D490000` 1워드만  
**주소:** `%DB980000`, Data Count=`02 00`

#### 요청 (총 42바이트, Count만 다름)

```text
4C 53 49 53 2D 58 47 54 00 00 00 00 A0 33 02 00 16 00 00 00
54 00 14 00 00 00 01 00 0A 00 25 44 42 39 38 30 30 30 30 02 00
```

| 필드 | HEX |
|------|-----|
| Invoke ID | `02 00` |
| Length | `16 00` (22) |
| Command / Type | `54 00` / `14 00` |
| Var Name | `%DB980000` |
| Data Count | `02 00` (2바이트) |

#### 응답 예시 (Data = `05 00` → 워드 값 5)

```text
4C 53 49 53 2D 58 47 54 00 00 04 01 A0 11 02 00 0E 00 00 2F
55 00 14 00 00 00 00 00 01 00 02 00 05 00
```

| 필드 | HEX | 의미 |
|------|-----|------|
| Source | `11` | PLC→PC |
| Invoke | `02 00` | echo |
| Command | `55 00` | Read 응답 |
| Error | `00 00` | 정상 |
| Data Count | `02 00` | 2바이트 |
| Data | `05 00` | D490000=`0x0005` → bit0·bit2 ON |

| 0~19 | 20 | Header | `… A0 33 03 00 14 00 00 00` |
| 20 | 2 | Command | `54 00` |
| 22 | 2 | Data Type | `02 00` (WORD) |
| 24 | 2 | Reserved | `00 00` |
| 26 | 2 | Block Count | `01 00` |
| 28 | 2 | Var Length | `0A 00` |
| 30 | 10 | Var Name | `25 44 57 34 39 30 30 30 30` = `%DW490000` |

원본 HEX:

```text
4C 53 49 53 2D 58 47 54 00 00 00 00 A0 33 03 00 14 00 00 00
54 00 02 00 00 00 01 00 0A 00 25 44 57 34 39 30 30 30 30
```

#### 응답 예시 (값 `0x0005`)

```text
4C 53 49 53 2D 58 47 54 00 00 04 01 A0 11 03 00 0E 00 .. ..
55 00 02 00 00 00 00 00 01 00 02 00 05 00
```

| App 필드 | HEX | 의미 |
|----------|-----|------|
| Command | `55 00` | Read ACK |
| Data Type | `02 00` | WORD |
| Error | `00 00` | 정상 |
| Block | `01 00` | 1변수 |
| Data Count | `02 00` | 2바이트(워드) |
| Data | `05 00` | 값 5 |

### 3.6 예시 D — 개별 BIT 읽기 (`%DX490000.0`)

| 항목 | 값 |
|------|-----|
| Data Type | `00 00` (BIT) |
| Var Name | `%DX490000.0` (ASCII, length=`0B 00` = 11) |

요청 App 골격:

```text
54 00 00 00 00 00 01 00 0B 00
25 44 58 34 39 30 30 30 30 2E 30   # "%DX490000.0"
```

응답 Data는 보통 1비트(또는 1바이트에 0/1). Error=`00 00`이면 정상.

## 5. 구현 시 주의

1. **Modbus / MC Protocol 아님.** XGT Dedicated 바이너리 프레임만 사용.
2. 연속 읽기 주소는 **`%DBxxxx`(바이트)**. 개별 WORD는 **`%DWxxxx`**.
3. 응답 Data는 LE 워드로 묶고, 비트는 §2.2 맵으로 해석. PLC↔PC 비트 반전은 현장 1점으로 확인.
4. 원본 맵 이슈: `D490011` 이중 할당, 자동시험기 `D490066.5` 점프 — PLC 담당과 확정 후 반영.
5. DWORD(`D490026~027` 등)는 워드 2개를 상위(앱/게이트웨이)에서 결합.
6. 응답 Length·Position·BCC는 모듈/펌웨어에 따라 달라질 수 있음 → Error Status·Data Count·Data를 우선 파싱.
